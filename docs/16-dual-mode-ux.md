# 双轨制 UX：平民模式 / 极客模式（P3，定稿，未开工）

> **状态：定稿。** 这是 P3 公开阶段的设计，前置门禁是 M6「连续 14 天日常使用」完成、
> M7 内测跑完一轮。门禁之前不改代码，只维护这份文档。

## 要解决的问题

Starveil 的自我定位同时是「极客自用神器」和「Top 1 大众产品」。这两件事不矛盾，但
**默认界面只能服务一个**。双轨制不是两套功能，而是同一份内核、同一份配置的两种信息
密度：下限低到扫码就能用，上限高到能编排出站链。

## 模式是什么

模式是**纯 UI 偏好**，不是配置开关：

- 存一个 `expert_mode: Boolean`（DataStore，默认 false）。
- 切换只改变哪些入口可见，**不重建配置，因此不重连**。
- 任务书里「复用 `startOrReloadService` 热更新」的假设不成立：P0 已实测，在活着的
  服务上调用它会让新实例等旧实例持有的 cache 数据库，报
  `initialize cache-file: timeout`；可靠换配置只有「完整拆掉 → 等 VpnService 为空 →
  再启动」。双轨制不需要换配置，所以绕开了这个问题，但不要把它当成热切换的先例。

## 平民模式（默认）

### 首页

只保留三样：

1. HUD 连接核心（现有的四态渲染）。
2. 节点选择卡片（当前节点、延迟、健康曲线；不展示协议参数）。
3. 三态模式切换：智能分流 / 全局代理 / 直连（映射到现有 `RoutePreset`）。

### 导入后的自动流水线

扫码、剪贴板或单链接导入成功后，不再让用户去规则页配置，而是自动完成：

```
导入成功
  → 确保规则集（大陆预设 + 去广告）就绪
  → 对所有节点做一次批量探测（NodeHealthBatchProbe）
  → 写入默认策略：BYPASS_MAINLAND + blockAds = true
  → NodePicker 选出最佳节点并选中
  → 连接
```

每一步都有现成实现，平民模式只是把它们串起来，并给出一个「正在准备…」的进度态：

| 步骤 | 现有能力 |
| --- | --- |
| 规则集 | `MainlandRuleSetStore.ensure()` / `ensureAds()` |
| 批量探测 | `NodeHealthBatchProbe.run()`（每节点一次 TCP 握手） |
| 选点 | `NodePicker.recommend()` |
| 连接 | `ConnectionController.connect()` |

失败处理：规则集下载失败不阻断连接（与现有预设的降级一致）；探测全失败时仍然连接，
只是不声称「最优」；连接失败给出可读原因并留在首页。

### 隐藏的入口

规则表、规则市场、节点编辑、按应用分流、场景、本地 API、备份、日志，全部不在平民
模式的导航里出现。设置页底部留一行「切换到极客模式」，切换后恢复现有五个 tab。

### 与新手引导的衔接

P3-4 的三步引导走完（或跳过后）直接落在平民模式；引导里的「自动选择并连接」与上面
的流水线是同一段代码，不新增第二条路径。

## 极客模式

保留现有全部页面，另加两项：

### 1. 可视化规则链

- 拖拽调整优先级：复用现有 `RulesViewModel.move()` 的重排序语义（整表重新编号），
  不新增数据结构。
- 命中实时高亮 / Live Hit Counter：数据源是 `FlowRecord.rule`（内核已经在每条连接上
  报命中的规则）。在 app 侧按规则聚合即可，不改内核。需要定一个滑动窗口（建议与
  「最近流向」一致），并明确计数是**连接数**而不是字节数——后者内核目前不按规则给。

### 2. 出站链编排

- 目标形态：落地节点 → WARP 双栈出口；前置节点 → REALITY 穿透。
- **verify first，未定稿**：需要确认当前 `starveil-1.14.x` 的 outbound 是否支持
  `detour` 链（sing-box 的部分出站有 `detour` 字段，但并非全部，且链式出站的 DNS
  与 sniff 行为需要实测）。确认之前不写 UI。
- 如果内核不支持：一期只做「出站列表 + 每跳的连通性/延迟」，把「链」留到内核支持
  之后；不在 app 层伪造一条链。

### 3. 模式切换

设置页顶部的开关，写入 `expert_mode`，立即生效；不触碰内核。

## 验收

- 拖拽改一次规则优先级，实时生效且 Hit Counter 数字变化。
- 两跳出站链连通，IP 显示为最终出口。
- 中文文案齐全；深色模式无白色泄漏（沿用 P2-1 的走查标准）。
