# 03 · 顶级产品设计指南（Starveil）

> 定位：自用优先，自用 OK 后推广发布。本文定义"顶级"是什么、怎么验证、怎么过渡，以及**不做什么**。
> 与文档一、文档二的关系：文档一审计架构（能不能做），文档二定义视觉（长什么样），本文定义产品标准（做到什么程度才算好）。

---

## 1. "顶级"的定义：五个维度 + 可检验标准

"顶级"不是形容词，是检查表。每个维度都必须能用"是/否"检验。

### Craft（工艺）——每个细节都被打磨过

| # | 可检验标准 |
|---|---|
| C1 | 全部界面无裸色值、无裸间距、无硬编码文案（查 `Color(0xFF`、`16.dp` 裸值、`"待实现"` 等字符串即判定失败） |
| C2 | 全部界面遵循文档二的 Token（色板、字阶、间距、圆角），抽查 3 个界面零违规 |
| C3 | 状态切换全部有动效（连接/断开/阻断/警告），无"瞬变" |
| C4 | 零占位文案上线（"待实现"、"TODO"、"Demo" 不得出现在发布包） |
| C5 | 空状态、错误状态、加载状态都有设计（不是空白页或 Toast 了事） |

### Consistency（一致性）——任何两个界面看起来是同一个产品

| # | 可检验标准 |
|---|---|
| K1 | 同一概念在全 App 只有一种表达（"延迟"不出现"延时/时延"两种叫法；"多拦/漏放"不出现"误杀/漏控"） |
| K2 | 同一操作在全 App 只有一种交互（删除都用滑动 + 撤销 Snackbar；确认都用对话框） |
| K3 | 导航、BottomBar、卡片、按钮、对话框在全 App 只有一套实现（无各处复制的变体） |
| K4 | 文案语气一致：专家模式、短句、无感叹号营销语 |

### Performance（性能）——快到感觉不到

| # | 可检验标准 |
|---|---|
| P1 | 冷启动到可交互 < 800ms（Macrobenchmark，见实施计划 §3.1） |
| P2 | 任何操作 < 100ms 有反馈（按钮按压、开关切换、导航跳转） |
| P3 | 节点列表滚动 120fps 无掉帧（1000 节点） |
| P4 | 后台常驻内存 < 80MB；断线重连 < 3s 自动恢复 |
| P5 | 动画期间帧率 ≥ 60fps；离开页面动画立即停止（无后台动画耗电） |

### Delight（愉悦感）——用起来有"爽"的瞬间

| # | 可检验标准 |
|---|---|
| D1 | 首次连接成功时，用户能说出"哇"（连接核心点亮 + 辉光 + 触觉，三者同步） |
| D2 | 日常操作路径 ≤ 2 步（连接、切节点、看延迟、看日志，全部 ≤ 2 步） |
| D3 | 界面有生命感：静止超过 2 秒的界面有呼吸或微动（见文档二 §1） |
| D4 | 聪明而非打扰：自动选路、断线自愈、订阅更新都在后台完成，成功时不弹窗 |

### Trust（信任）——用户敢把凭证托付给它

| # | 可检验标准 |
|---|---|
| T1 | 日志、分享、备份、崩溃上报四处均脱敏（用扫描工具验证：日志中无 UUID/密码/私钥/完整订阅 URL） |
| T2 | 失败时说实话：订阅失败显示真实原因 + 保留上次可用配置；不编造"已连接"状态 |
| T3 | 敏感操作二次确认（删除订阅、导出配置、清除数据） |
| T4 | 隐私政策可读：写清收集什么、不收集什么；崩溃上报可关闭 |
| T5 | 更新双校验（SHA-256 + 签名指纹）；失败时给出官方下载页，不静默失败 |

**验收方式**：每个里程碑结束时，按本节 23 条逐条打勾。未全过 = 未达"顶级"，不进入下一阶段。

## 2. 质量门禁清单：每种场景的体验标准

| 场景 | 体验标准 |
|---|---|
| **首次启动** | 1 秒内进入 Dashboard；空状态有引导（"导入订阅"主按钮 + "手动添加"次按钮）；不弹权限（权限在需要时才申请） |
| **空状态（无节点/无订阅）** | 核心黯淡 + 明确文案 + 可操作的按钮；禁止空白页、禁止只用 Toast 提示 |
| **订阅失败** | Snackbar 显示真实原因 + "重试" + "查看详情"；**保留上次可用配置**，禁止清空已有节点；失败不覆盖可用 Profile（见实施计划 P1-4） |
| **内核崩溃** | 核心 BLOCKED 态 + "内核已停止" + "重试" + "查看日志"；自动尝试重启 1 次，失败后停住并明确告知，不无限重启 |
| **无网络** | 核心 DISCONNECTED + "无网络连接"；不误报为"内核故障"；网络恢复后自动重连 |
| **离线** | 已有节点/规则可用；订阅更新跳过并标注"离线，未更新"；不弹错误 |
| **弱网** | 乐观 DNS 缓存生效；超时提示明确（"节点响应超时"而非"失败"）；测速超时不卡界面 |
| **断线重连** | 指数退避自动重连；重连中显示"重连中（第 N 次）"；重连成功不弹窗；重连失败 3 次后停住并告知 |
| **后台被杀** | 前台服务 + 保活引导；被杀后下次打开显示"上次被系统回收"，并给厂商白名单引导入口 |
| **权限拒绝** | 通知权限被拒 → 通知栏功能降级，App 内提示一次，不反复索要；VPN 权限被拒 → 明确告知"没有 VPN 权限无法代理"，给"重新授权"按钮 |
| **存储空间不足** | 备份/导出失败时明确告知原因，不静默失败 |
| **配置非法** | 导入非法订阅/节点时指出具体错误（"第 N 行格式错误"），不只说"导入失败" |

## 3. 自用验证清单：什么叫"自用 OK"

> 自用阶段的目标：**在你一个人、真实网络、真实设备上，跑满一个完整使用周期**，证明它配得上"神器"二字。

### 3.1 验证场景（全部要跑，缺一不可）

| # | 场景 | 通过标准 |
|---|---|---|
| V1 | 日常通勤（地铁/公交，网络频繁切换） | 连续 5 个工作日，无手动干预不断线；切换网络后 < 3s 自动恢复 |
| V2 | 弱网（电梯、地下车库、郊区） | 能连上且可用；不出现"假连接"（显示已连接但打不开网页） |
| V3 | 长时间后台（息屏 8 小时） | 唤醒后无需手动重连；电池消耗在系统统计中不进前三 |
| V4 | 节点切换 | Dashboard 内 2 步内切节点；切换后 1s 内流量通 |
| V5 | 订阅更新 | 自动更新成功；更新失败时保留旧配置且有提示 |
| V6 | 按应用分流 | 银行 App 直连、AI App 走低延迟节点，各 3 次验证通过 |
| V7 | 规则命中 | 自定义规则生效；规则页能看到"当前哪条规则在生效" |
| V8 | 日志定位 | 模拟一次断线，用日志屏在 2 分钟内定位原因 |
| V9 | 崩溃恢复 | 模拟内核崩溃（kill 进程），App 自动重启内核或明确告知，不卡死 |
| V10 | 备份恢复 | 导出加密备份 → 清除数据 → 导入恢复，节点/规则/设置全部回来 |

### 3.2 "自用 OK"的退出条件（全部满足才算 OK）

1. **连续 14 天**日常使用，零手动救火（不需要你为它修任何东西）。
2. **零"假连接"**：从未出现"显示已连接但打不开网页"。
3. **零凭证泄露**：日志扫描、分享导出、备份三处均无敏感字段（用扫描工具验证，见 §1 T1）。
4. **性能目标**（§1 P1–P5）全部达标。
5. **你自己愿意删掉 Mirage**：主观标准，但最真实——当你不再打开旧 App 时，自用验证才算通过。

**未满足退出条件时**：不进入推广阶段。推广不是"写个 README 就发"，是"自用 OK"之后的自然延伸。

## 4. 自用 → 推广的过渡计划

### 阶段 A：自用验证（本计划 Phase 0–5）

- 只服务一个人；文案可以只有中文；无隐私政策；无反馈通道（你自己就是反馈）。
- 唯一交付物：§3 的退出条件全部满足。

### 阶段 B：内测（1–3 个可信用户）

| 要补的东西 | 说明 |
|---|---|
| 中英双语 | `values-zh` 全量翻译；文案进 `strings.xml` |
| 隐私政策 | App 内 + GitHub 各一份（见文档一 §6-3） |
| 崩溃上报 | Sentry / Crashlytics，上报前脱敏，提供关闭开关 |
| 反馈通道 | GitHub Issue 模板（Bug / Feature，各中英一份，参考 Mirage 的模板） |
| 更新通道 | GitHub Releases 检查 + 双校验（见文档一 §6-5） |
| 更新日志 | CHANGELOG.md，Keep a Changelog 格式 |
| 内测说明 | README 增加"内测版"声明：已知问题、反馈方式、不承诺 SLA |

### 阶段 C：公开推广

| 要补的东西 | 说明 |
|---|---|
| 完整 i18n + 伪本地化测试 | `en-XA` 伪本地化跑一遍，抓硬编码文案 |
| 无障碍走查 | TalkBack + 大字体 + 对比度（见文档二 §9） |
| 多设备覆盖 | WindowSizeClass 自适应；横屏/平板/折叠屏 |
| Play 合规（如上架） | 前台服务类型申报、数据安全表单、目标 SDK |
| 发布流程 | 版本号策略（semver + versionCode 单调）+ 发布检查表（见下） |
| 品牌资产 | 图标、截图、README 徽章、GitHub 社交预览图 |

**发布检查表**（每次发版前逐条打勾）：

- [ ] §1 的 23 条顶级标准全部通过
- [ ] CHANGELOG 已更新
- [ ] 版本号按策略递增
- [ ] R8 混淆后回归测试通过
- [ ] 日志/分享/备份/崩溃上报四处脱敏扫描通过
- [ ] 隐私政策与代码行为一致（代码新增收集项时同步更新政策）

## 5. 不要做的事（防止范围蔓延）

| # | 不做 | 理由 |
|---|---|---|
| 1 | **不做新手教程 / 引导动画** | 自用不需要；推广阶段只做"三步引导"（导入→选节点→连接），不做交互式教程 |
| 2 | **不做 20 种语言** | 自用中英即可；推广阶段也只加"有人主动贡献翻译"的语言，不主动铺 |
| 3 | **不做 TV / 车机 / 手表** | 形态不同 = 新产品；Starveil 是手机产品，TV 界面不做 |
| 4 | **不做"AI 选节点"卖点** | 没有可验证机制前不宣传（见挖掘报告"明确不建议"）；健康历史评分是工程，不是 AI 噱头 |
| 5 | **不做自研规则集市场标准** | 只做客户端聚合（订阅规则集），不定义市场标准 |
| 6 | **不做社交 / 分享节点 / 节点测评** | 节点分享是隐私与法律风险；Starveil 不做任何节点内容 |
| 7 | **不做内置购买 / 订阅付费** | 自用神器不收费；推广阶段也保持免费开源（GPL），不接支付 |
| 8 | **不做 ECH 默认开启** | 收益有限、成本高；REALITY 已覆盖 SNI 伪装需求 |

**判断规则**：新功能提议时问三句——① 我每周会用三次以上吗？② 它让"神器标准"更近了吗？③ 它增加的维护成本值得吗？三句有一句"否"，就不做。

## 6. Roadmap（产品里程碑视角）

> 与实施计划六阶段对齐，但这里只写**用户可感知**的交付物。技术任务见实施计划，产品里程碑见下表。

| 里程碑 | 用户可感知交付物 | 退出条件 |
|---|---|---|
| **M0 · 止血** | 无（后台工作） | 仓库无密钥；日志扫描无敏感字段 |
| **M1 · 骨架** | 能打开的 App：Dashboard 核心可点、五屏可切换、Fake 内核跑通连接流程 | 编译通过；§1 C1–C3 通过 |
| **M2 · 内核** | 真实连接：能导入真实订阅、连上真实节点、流量真实走通 | V4（节点切换）+ V5（订阅更新）通过 |
| **M3 · 界面** | 驾驶舱成型：连接核心动效完整、节点健康曲线、规则流向图、日志筛选 | §1 C1–C5、K1–K4 通过；日常操作 ≤ 2 步 |
| **M4 · 性能** | 快：冷启动 < 800ms、滚动 120fps、后台 < 80MB | §1 P1–P5 全部达标（Macrobenchmark 数据） |
| **M5 · 智能** | 聪明：自动选最优节点、切网络自动恢复、按应用选节点、AI 分组 | §3 V1–V7 通过 |
| **M6 · 打磨** | 完整：Widget / Tile / 通知栏快切、备份加密恢复、无障碍基础 | §3 退出条件 1–5 全部满足 → **自用 OK** |
| **M7 · 内测** | 别人能用：中英双语、隐私政策、崩溃上报、反馈通道 | 3 个内测用户各跑 7 天无阻塞问题 |
| **M8 · 公开** | 公开发布：GitHub 公开 + 发布检查表全过 | 发布检查表（§4）全部打勾 |

**一句话总结**：M1–M2 证明"能用"，M3–M4 证明"好用"，M5–M6 证明"神"，M7–M8 证明"别人也能用"。跳过任何一步，都是在透支信任。
