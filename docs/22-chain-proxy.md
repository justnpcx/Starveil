# 22 · 链式代理（0.9.17）

## 模型

链是出口节点的一个属性，不是新节点类型。`Profile.frontNodeKey` 指向一个前置节点；出口被选中时，`ConfigBuilder` 为前置生成独立 outbound / endpoint，并在出口的 outbound 上写 sing-box 原生 `detour`。路由、DNS、预设和规则顺序不变。

只开放一层：选择器排除出口自身与已经带前置的节点，因此环在构造上不可能出现。前置自己的 `frontNodeKey` 不在本链中递归展开；它只在该节点自己作为出口时生效。

引用键是 `type|server|port|name`，不是数据库行 id。订阅刷新采用删后重插，行 id 不稳定，而业务键与导入去重使用同一元组。刷新保留相同业务键上的用户前置设置；前置消失、自指或所在分组删除时，数据层立即清除引用，写 WARN，并给节点页发送一次性提示。

## 测速与健康口径

无前置节点沿用原有 TCP 探针，行为不变。带前置节点使用 `ConfigBuilder.buildProbe` 生成无 tun 的独立 SOCKS 配置；其中的协议 fragment 与正式配置同源，请求实际经过完整 front → exit detour。手动测速、前台采样和批量探测共用这条选择逻辑。

整链成绩只记到出口节点：自动选择仍使用同一候选池与同一评分标准，不另设链池，也不连带扣前置自身的单跳成绩。出口 IP 请求成功同样是整链可用证据，会写入成功健康样本。

节点行的延迟、不可达标记与超时折叠统一跟随最新样本；30 分钟窗口的在线率与 POOR 信誉只呈现在健康卡，不再把最新成功覆盖成 DOWN。解析失败与连接失败分开，解析失败不产生不可达样本。

## 导入、分享与诊断

sing-box JSON 导入把指向同文件另一 outbound 的 `detour` 映射为前置，导出再导入保留该关系。单节点 URI 无法表达第二跳，分享界面必须明示不包含前置设置。

连接失败只按 sing-box 错误文本中的 outbound tag 归因；无法区分时写「链路失败（未分段）」，不猜。诊断页对当前链分别显示前置单跳与出口整链的最新结论，无前置时该行不存在。
